# Работа с лабораторией

## Добавить статью

1. Выбери статью из [коллекции](https://disk.360.yandex.ru/d/IgLFLct2HZKq_Q), запиши авторов, год и исходную ссылку.
2. Создай папку `papers/Author_Year_Short_Title/` и карточку `README.md` по шаблону.
3. Сохрани PDF с устойчивым именем и метаданные в `metadata.json`. Не меняй имя после появления ссылок.
4. Добавь `Author_Year_translation_ru.md` и рисунки в `assets/`. Сохрани нумерацию формул, рисунков и таблиц. Помечай пояснения переводчика.
5. Свяжи сложные места перевода с поясняющими заметками. Общие понятия положи в `notes/`, особенности алгоритма оставь рядом со статьёй.
6. Добавь строку в `papers/README.md` и ссылку в `Home.md`.
7. Выполни `python3 scripts/check_links.py`.

## Добавить код

Для начала изучения удобно хранить снимок исходников непосредственно в `papers/<paper_id>/code/<implementation>/`: его можно править вместе с русскими заметками в одном commit. Вложенные `.git` и результаты сборки в снимок не входят.

Для каждой реализации фиксируй upstream URL, полный SHA исходного commit, лицензию, состояние локальных изменений и инструкцию запуска. Официальный код статьи и сторонние реализации обозначай отдельно. Если начнёшь регулярно подтягивать изменения upstream, перенеси реализацию в отдельный fork и подключи закреплённым submodule; сохраняй путь или обновляй ссылки.

Сборку выполняй в игнорируемой папке `build/`. Записывай изменения поведения и тесты, которыми они проверены. Файлы из другого репозитория не получают автоматически лицензию лаборатории.

## Добавить контейнер

Сначала добейся воспроизводимой сборки одной реализации, затем добавь её Dockerfile в `code/containers/` и команды в `code/README.md`. Фиксируй базовый образ, зависимости, целевую архитектуру и точку входа. Данные подключай внешним томом, результаты записывай отдельно от исходников.

Проверяй контейнер на короткой последовательности: запуск, сохранение траектории, отсутствие потерь данных и совпадение метрик с обычным запуском. Сборка для x86_64 не подтверждает работоспособность на ARM64/Orange Pi.

## Добавить датасет

Датасет получает общую карточку в `datasets/` и локальные данные в `data/`. В карточке укажи сайт, лицензию, сенсоры, калибровку, часы устройств, формат времени и эталонные данные. Статьи и эксперименты ссылаются на ту же карточку.

Если меняешь формат, сохраняй исходные записи и код преобразования. Для собственного датасета ВМК отдельно храни сырые измерения, параметры синхронизации, преобразования между сенсорами и происхождение опорной траектории.

## Ссылки Obsidian

Открывай корень репозитория как одно хранилище. Для уникальных имён достаточно `[[note_name]]`; для повторяющихся `README` указывай полный путь от корня. Рисунки подключай относительными Markdown-ссылками, например `![Рисунок](assets/figure_01.png)`.

Перенос файлов делай через Obsidian с включённым обновлением ссылок. При переносе вне приложения запускай проверку ссылок. Шаблоны ещё не являются заполненными заметками и исключены из проверки.

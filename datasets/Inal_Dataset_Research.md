 Сравнение датасетов для проекта SLAM

Я решил посмотреть несколько датасетов, которые можно использовать в нашем проекте. Главная задача найти подходящие данные для проверки работы MonoSLAM

для меня было важно, чтобы в датасете были изображения с камеры, информация о движении камеры или робота и, желательно, эталонная траектория, с которой можно сравнить результат работы алгоритма

для начала я выбрал три варианта EuRoC MAV, TUM VI и OpenLORIS-Scene

 1 EuRoC MAV

этот датасет был создан для исследований с небольшими летательными аппаратами (дронами)

В нём есть:
 две чёрно-белые камеры
 частота записи камер  20 кадров в секунду
 IMU с частотой 200 Гц
 эталонная траектория, полученная с помощью системы оптического захвата движения

одно из преимуществ EuRoC  достаточно точная эталонная траектория. Это позволяет проверить, насколько правильно алгоритм определяет положение камеры

но есть и ограничение, данные записывались преимущественно с дрона, поэтому условия движения отличаются от движения обычного колёсного робота

Для нашего проекта: датасет подходит для первых экспериментов. Поскольку MonoSLAM работает с одной камерой, можно использовать изображения только с одной из двух камер, не задействуя вторую и IMU

 2 TUM VI

TUM VI ещё один известный датасет для проверки визуальной и визуально-инерциальной одометрии

В отличие от EuRoC, здесь представлены более разнообразные условия съёмки: помещения и улица. Камера перемещается в руках человека, поэтому в данных встречаются повороты и достаточно резкие движения

Основные характеристики
 две серые камеры
 частота записи — 20 кадров в секунду
 IMU BMI160 — 200 Гц
 изображения с разрешением 1024 × 1024
 эталонная траектория, полученная с помощью системы захвата движения

Главная особенность этого датасета — разнообразие движений камеры. Это полезно, поскольку алгоритму приходится работать не только с плавным перемещением, но и с более сложными движениями

Для нашего проекта можно взять изображения с одной камеры и проверить, насколько устойчиво MonoSLAM отслеживает движение. Нужно учитывать особенности объектива и калибровку камеры

 3 OpenLORIS-Scene

Этот вариант мне показался особенно интересным, потому что данные собирались не просто с отдельной камеры, а с реальных мобильных роботов.

Роботы перемещались по офисам, торговым центрам и другим помещениям. Поэтому датасет ближе к условиям, в которых SLAM может использоваться на практике

В состав оборудования входят:
 Intel RealSense D435i
 Intel RealSense T265
 IMU
 лазерный дальномер Hokuyo
 датчики колёсной одометрии

также в датасете есть эталонные траектории полученные с помощью системы OptiTrackK или лазерной системы

здесь встречаются люди, движущиеся объекты, разные  освещениT и повторные посещения одних и тех же помещений

для нашего проекта  можно использовать изображения с одной камеры, а остальные данные оставить для дополнительной проверки результатов. Это позволит посмотреть, как MonoSLAM ведёт себя в более сложных условиях

 что лучше использовать для MonoSLAM?

У MonoSLAM есть важная особенность алгоритм изначально рассчитан на работу с одной камерой. Поэтому наличие IMU, лидара и других датчиков в датасете не является обязательным

При этом дополнительные данные могут пригодиться для проверки точности полученной траектории.

я бы предложил двигаться следующим образом

 Сначала попробовать EuRoC MAV, поскольку у него есть точная эталонная траектория и данные с камер
 Затем проверить алгоритм на TUM VI, где условия движения камеры более разнообразные
 После этого перейти к OpenLORIS-Scene, чтобы посмотреть на работу алгоритма в условиях приближённых к реальному использованию робота

На данный момент это предварительный выбор по характеристикам датасетов. Перед полноценными экспериментами ещё нужно проверить формат изображений, параметры калибровки и возможность загрузки данных в MonoSLAM
